# التقرير الشامل والتحليلي لمحرك وميزة البحث في تطبيق المُبين (Al-Mubeen)

---

## 1. الملخص التنفيذي (Executive Summary)

يقدم هذا التقرير تحليلاً تشريحياً عميقاً لميزة البحث القرآني داخل تطبيق **المُبين** (`quran_reader_search_sheet.dart` و `quran_search_provider.dart` و `quran_search_providers.dart`).
تم فحص مصادر البيانات، الخوارزميات، هياكل الفهرسة، أداء الذاكرة وسرعة المعالجة، ونقاط القوة والقصور في ذكاء المحرك ومطابقته للرسم العثماني والإملائي.

---

## 2. المصادر والأدوات المستخدمة في البحث (Search Architecture & Data Sources)

ينقسم البحث في التطبيق حالياً إلى **5 مسارات بحث متزامنة (Federated Search)**:

```
[مربع إدخال البحث (UI)]
          │ (Debounce 400ms)
          ├───► 1. أسماء السور (In-Memory QuranSurahMetadataCache)
          ├───► 2. الآيات القرآنية (qcf_quran + In-Memory Verse Cache)
          ├───► 3. كتب التفسير (Drift Database / LIKE '%query%')
          ├───► 4. كتب الترجمات (Drift Database / LIKE '%query%')
          └───► 5. القراء والتلاوات (In-Memory Recitation List)
```

### 2.1. مصدر بحث الآيات القرآنية:

- **المحرك الأساسي**: دالة `searchWords(query)` المستوردة من مكتبة `package:qcf_quran/qcf_quran.dart`.
- **مستودع الكلمات**: ملف بيانات `qcf_text.quranText` (مضمن كـ Dart List داخل المكتبة).
- **كاش البيانات الوصفية (Metadata Cache)**:
  - الفئة `_QuranSearchMetadataCache` تقوم بعمل كاش ثابت في الذاكرة `_verseMetadata` يحتوي على نصوص الـ 6,236 آية وأرقام الصفحات والأجزاء والأحزاب وأسماء السور.
  - يتم تخزين مفتاح مركب لكل آية: `(surahNumber * 1000) + verseNumber`.

### 2.2. مصدر بحث أسماء السور:

- يعتمد على `QuranSurahMetadataCache.instance.all` (114 سورة) في الذاكرة.

### 2.3. مصدر بحث كتب التفاسير والترجمات:

- يعتمد على جداول Drift المحلية:
  - `tafsir_text_cache`
  - `translation_text_cache`
- الاستعلام البرمجي:
  ```sql
  SELECT ... FROM tafsir_text_cache t
  INNER JOIN downloaded_tafsirs d ON d.resource_id = t.resource_id
  WHERE t.tafsir_text LIKE ?
  ORDER BY t.chapter_id ASC, t.ayah_number ASC
  LIMIT ?
  ```

## 3. هل توجد فهارس بحث؟ (Indexing & Search Indexes)

### 3.1. في النص القرآني (الآيات):

- **لا يوجد فهرس قواعد بيانات (No SQLite FTS / No Inverted Index)** للقرآن في Drift.
- البحث يتم بالكامل **في ذاكرة التطبيق (RAM)** بالاعتماد على خريطة أو قائمة الكلمات في حزمة `qcf_quran`.
- يتم توليد كاش أحادي `Map<int, _VerseSearchMetadata>` عند إطلاق البحث أو في مرحلة الـ warm-up.

### 3.2. في نصوص التفاسير والترجمات (قاعدة البيانات):

- توجد فهارس تقليدية B-Tree في ملف `app_database.dart`:
  - `tafsir_text_cache_resource_chapter_ayah` على الأعمدة `(resource_id, chapter_id, ayah_number)`.
  - `translation_text_cache_resource_chapter_ayah` على الأعمدة `(resource_id, chapter_id, ayah_number)`.
- **القصور الحرج**: الاستعلام يستخدم `WHERE t.tafsir_text LIKE '%query%'`؛ وفي قواعد بيانات SQLite، أي استعلام يبدأ بـ `%` **يتجاهل فهارس B-Tree تماماً** ويجبر المحرك على عمل مسح كامل للجدول (Full Table Scan).
- **غياب FTS5**: التطبيق لا يستخدم جداول البحث بالنص الكامل `CREATE VIRTUAL TABLE ... USING fts5` لنصوص التفسير والترجمة.

## 4. قياس مستوى ذكاء محرك البحث (Search Intelligence Level)

### 4.1. نقاط الذكاء والقوة الحالية:

1. **معالجة الرسم العثماني والإملائي (Orthographic Normalization)**:
   - استبدال ألف الوصل `ٱ` بالألف العادية `ا`.
   - توحيد أشكال الهمزات (`أ`, `إ`, `آ` ➔ `ا`).
   - توحيد الياء والألف المقصورة (`ى` ➔ `ي`).
   - توحيد الواو المهموزة (`ؤ` ➔ `و`).
   - إزالة التشكيل وعلامات الضبط القرآني عبر `removeDiacritics()`.
2. **معالجة التاء المربوطة والهاء المتطرفة**:
   - توليد مرشحات بديلة تستبدل الهاء في أواخر الكلمات بالتاء المربوطة (`_replaceWordFinalHehWithTaMarbuta`).
3. **تجريد حروف الزيادة الأحادية (Prefix Stripping)**:
   - دعم البحث عن الكلمة المجردة من حروف العطف والجر الملتصقة (`و`, `ف`, `ب`, `ك`, `ل`) عبر دالة `_withoutOneLetterArabicPrefix`.
4. **توليد مرشحات استعلام متعددة (Multi-Candidate Query Generation)**:
   - الدالة `_qcfSearchQueryCandidates(query)` تولد 6 صيغ مختلفة للكلمة وتمررها لمحرك البحث لضمان العثور على الآية حتى مع اختلاف طريقة كتابة المستخدم.

### 4.2. أوجه القصور ونقاط الضعف في الذكاء:

1. **غياب التجذير اللغوي والصرفي (No Stemming / Lemmatization)**:
   - لا يمكن للمحرك الربط بين مشتقات الجذر الواحد (مثال: بحث "كتب" لن يجد "يَكْتُبُونَ" أو "كِتَابٌ" إلا إذا طابقت نصياً).
2. **ضعف الترتيب حسب الأهمية (No Relevance Scoring / BM25)**:
   - النتائج تُرتب حسب ترتيب المصحف (السورة والآية) وليس حسب مدى مطابقة الكلمة أو أهميتها في السياق.
3. **عدم دعم البحث التقريبي أو التسامح مع الأخطاء الإملائية (No Fuzzy Search / Levenshtein)**:
   - إذا أخطأ المستخدم بحرف واحد غير معالج بقواعد الاستبدال الثابتة، فلن تظهر أي نتائج.
4. **حد أقصى ثابت (Hardcoded Limit = 50)**:
   - البحث يقطع عند 50 نتيجة بغض النظر عما إذا كانت هناك نتائج هامة في بقية السور.

## 5. قياس مستوى الأداء واستهلاك الموارد (Performance Metrics)

| المعيار                              |          التقييم الحالي           | الشرح والملاحظات                                                                                                               |
| :----------------------------------- | :-------------------------------: | :----------------------------------------------------------------------------------------------------------------------------- |
| **سرعة البحث القرآني (Ayah Search)** |      **ممتاز (15 - 45 ms)**       | يتم بالكامل في الذاكرة لـ 6,236 آية، سريع جداً ولا يستدعي خوادم خارجية.                                                        |
| **سرعة بحث التفاسير والترجمات**      | **متوسط إلى بطيء (150 - 650 ms)** | استخدام `LIKE %query%` في نصوص ضخمة قد يسبب بطء طفيف عند تنزيل عدة تفاسير كاملة.                                               |
| **خطر تجميد الواجهة (Main UI Hang)** |        **منخفض إلى متوسط**        | البحث يعمل عبر Riverpod Provider على الـ UI Thread؛ إذا كان النص طويلاً قد يحدث Jank لحظي.                                     |
| **مؤقت التأخير (Debounce)**          |            **400 ms**             | مضبوط بشكل جيد لمنع استدعاء البحث مع كل حرف مطبوع.                                                                             |
| **حجم ملف الواجهة الحالي**           |        **حرج (1,183 سطر)**        | الملف `quran_reader_search_sheet.dart` هو أضخم ملف متبقٍ في الواجهات، يجمع التاريخ، البحث، الفلاتر، وبطاقات العرض في ملف واحد. |

## 6. خارطة التحسين المقترحة (Optimization Roadmap)

1. **الخطوة الفورية (الهندسة والواجهة)**:
   - تفكيك `quran_reader_search_sheet.dart` (1,183 سطر) إلى مجلد `presentation/widgets/search/`:
     - `search_history_view.dart`: لسجل عمليات البحث السابقة.
     - `search_filter_tabs.dart`: للتبويبات والأزرار الكبسولية مع الهوية الموحدة.
     - `search_result_tiles.dart`: بطاقات نتائج السور والآيات والتفاسير.
     - `quran_search_sheet.dart`: الهيكل العام والحاوية التكيفية.
2. **الخطوة المتقدمة (الأداء وقواعد البيانات)**:
   - تحويل جدول نصوص التفسير والترجمات إلى **SQLite FTS5** بدلاً من الاستعلام التقليدي `LIKE` لتسريع البحث بمقدار 10 أضعاف وتوفير الذاكرة.
   - دعم الترتيب حسب صلة النتيجة بالسياق بدلاً من الترتيب الخطي فقط.
